Agents write the code. Xo catches what they miss.

Xo (pronounced ex-oh) is a small, statically typed language for backends, tools, and web services. A human project owner oversees AI that builds and maintains the language. Things like ignored errors, nil, missed cases, and hidden side effects are compile errors in Xo. The compiler is optimized to return helpful information back to the agent (or human).

// why xo

Ideas from great languages, in one small one.

Xo borrows what has proven itself in Go, Rust, Swift, and Kotlin, and turns the bugs tests usually miss into compile errors. In a study of 30 planted safety bugs, Xo caught or prevented 23 to 29, against 13 for Go with strict analyzers and 9 for plain Go.

from Go

Small and fast

Few keywords, one obvious way, one formatter, fast builds, and static binaries for Linux, Mac, Windows, and WASI.

from Rust

Errors you can't ignore

Result and ?; an unhandled error is a compile error.

from Rust and ML

Sum types, exhaustive match

Every case handled, and every match target.os arm type checked for every target.

from Swift and Kotlin

No nil

Optionals are T? and checked at every use.

from Swift and Kotlin

Structured concurrency

No task outlives its scope; value semantics mean no data races.

Effects you can see

interop · Go

Use any Go package

Bindings are generated on the fly. (T, error) becomes T ! go.Error, and a nil pointer becomes T?.

Call C from native builds

The LLVM and arm64 backends bind C headers directly, with effects declared at the boundary.

// supply chain

A dependency can only do what you let it.

Put a ceiling on a dependency in xo.mod. If an upgrade starts doing more, the build fails at your call, before the new code ever runs. No mainstream language checks limits per dependency in the compiler: Go and Rust rely on audits and analysis tools, Deno and Node grant permissions per process, and Java's SecurityManager is disabled as of JDK 24.

an upgrade that reaches into Go
$ cat xo.mod
module example.com/shop

require github.com/acme/billing v1.4.1 uses none

  note: review why github.com/acme/billing needs `go`; then raise the ceiling,
  or require a version within it (decision 0086)
at compile time

What code may do

  • Authority is a value: a library gets the network, files, or processes only if handed them.
  • Every pub function declares its effects, checked against its body; logging is the log effect.
  • A ceiling per dependency in xo.mod (XO1309).
  • A dependency's Go and C code count only with your own vouch (XO1316).
at update

What changed

  • xo.lock records each dependency's effects; an update that reaches further fails until you accept it (XO1317).
  • xo get prints every API and effect change.
  • xo publish rejects a minor or patch release that adds an effect (XO1310).
  • Nothing runs at install: no hooks, no build scripts, no code on import.
at run time

Less than the whole thing

  • os.net.only(["api.example.com"]) reaches only those hosts; anything else is Denied before it happens.
  • Env.only, Proc.only, and Fs.sub narrow variables, commands, and directories.
  • task.with_budget caps the steps and running time of a call, so a dependency that loops forever is stopped.
  • xo audit reports every dependency's effects, escape hatches, log call sites, and the capabilities you pass it.

Measured: of 17 attack scenarios from the Backstabber's Knife Collection taxonomy, rebuilt as malicious Xo dependencies, Xo blocks 12, four of them with no setup. Hardening is opt-in, a vouch is your own review, and a wrong answer performs no effect, so tests remain the defense there; an endless loop is stopped only under a budget. // how it builds

One language, native by default.

Xo has five backends, and all of them start from the same SSA form. By default a program compiles to native code: on Apple silicon Macs and arm64 Linux, Xo's own arm64 backend, assembler, and linkers build the binary with no C toolchain; on x86-64 the default is LLVM for now, and Xo's own x86-64 backend, in preview, already builds Linux and Intel Mac binaries with no C toolchain. The native runtime is written in Xo, with no C, and frees memory by reference counting, with no garbage collector; a function marked uses realtime gets bounded loops, no recursion, and no allocation. Debuggers see your variables, structs, lists, and maps, and a profiler and an execution trace are built in. The Go backend is the other way to build the same program, and the WebAssembly backend runs it over WASI. Interop differs by backend: native builds can call C with use c, and the Go backend can call Go.

native · default on arm64

arm64 backend

Writes AArch64 assembly straight from Xo's SSA form, assembled and linked by Xo's own tools: fast builds on Apple silicon Macs and arm64 Linux, static Linux binaries from a Mac, and binaries smaller than LLVM's. The compiler builds itself with it.

xo build
native · preview

x86-64 backend

Xo's own code generator, assemblers, and linkers for x86-64 Linux and Intel Macs, built the same way as arm64's, with no C toolchain; Windows is next. Within about 14 percent of LLVM's instructions on our benchmarks, and closing (how).

xo build --backend=amd64
native · default elsewhere

LLVM backend

Lowers the same SSA form to LLVM IR and builds optimized native code with clang, for every native target, Windows included. The default on x86-64 hosts until Xo's own backend takes over.

xo build --backend=llvm
reference

Go backend

Writes Go source that points back to your .xo lines, for every Go target, with Go's garbage collector, and can use go any Go package.

xo build --backend=go
experimental

WebAssembly backend

Turns the same SSA form into WebAssembly that runs over WASI with its own runtime. It builds the compiler that runs the playground; a program it cannot build yet stops with a clear error, never with wrong output.

xo build --backend=wasm
all five

Same program, same output

Every backend is tested against the others: the test programs and randomly generated ones must print the same output on each, and every change to the compiler must rebuild it byte for byte.

// get xo

Build it from source.

There are no prebuilt downloads yet. The compiler is written in Xo, so the first build starts from Xo's last Go version and walks forward to today's; it needs git and Go 1.26 or later, once (and clang on x86-64), and took 25 to 37 minutes on a 16-core machine. After that, every xo builds the next one without Go, and native programs build with no C toolchain on Apple silicon Macs and arm64 Linux.

zsh
$ git clone {{ site.Params.sourceRepo }} && cd xo
$ go run ./scripts/xobuild --from-source
$ export PATH="$PWD/bin:$PATH"
$ xo init example.com/hello

A toolchain built for agents to drive.

Checks, builds, and queries answer in JSON. Lookups and edits work on resolved symbols, so an agent never guesses from text, and every edit is rechecked before it is written. dbg(x) prints a value from any function, pure ones included, on every backend, and a release build strips it. And when the check is clean, Finan sleeps soundly.
