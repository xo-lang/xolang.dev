Before code generation the native backends check every call, closure, and field or payload access against this build's definitions. A mismatch means a piece of the build came from a cache built under other definitions (a front end body that names a helper by a name this build gives another helper, gotchas/helper-name-creation-order.md): emitting the call would produce a binary that faults. The build stops instead. It is a compiler bug, not an error in the program.

## Example

```xo
# XO1510: http.fields_in: b27: v117: Str? = call xo.maph.logget[Map[Str, Str]] ...: result type does not match the callee
```

## Fix

```xo
# rebuild without the backend cache and report the message
XO_BACKEND_CACHE=off xo build .
```

Run `xo explain XO1510` for this text in a terminal, or see
[section 10.6 of the specification](../../spec/core/#106-diagnostic-codes).
