No build reports it today. It stopped a native build whose program used a std API the native runtime did not support on the target yet; the last ones were processes on Windows, ported on 2026-10-12 (decision 0197 stage 2), and Windows builds now default to Xo's own amd64 backend (decisions 0254, 0270). The code keeps its meaning in case a port is ever partial again; the message would name the parts, and the Go backend (`--backend=go`) would build the program.

## Example

```xo
> xo build --backend=llvm .
XO1504: the LLVM backend does not support processes (Proc) on windows yet (decision 0197); build with the Go backend (the default) instead
```

## Fix

```xo
# build with the Go backend, which supports every std API on Windows:
xo build .
```
